# 기존 영상 분석과 개선 우선순위

대상: 사용자 제공 `m2-res_290p.mp4`, 30.10초, 854×290, 30fps H.264. FFmpeg로 전체 파일을 디코딩하고 00~29초의 시점별 프레임을 검토했다. 영상에 오디오 스트림은 없다. 저해상도·편집된 비교 영상이므로 접촉 오차, 실제 FPS, 물리 모델의 내부 구현은 확정할 수 없다.

현재 작업 폴더에는 기존 Godot 프로젝트가 없었다. 새 프로젝트를 만들었으며 원본 MP4는 변경하지 않았다. 첨부 문서는 처음에는 참고 자료로 취급했고 사용자가 실제 제작 의도를 확인한 뒤 요구사항으로 채택했다.

## 우선순위 체크리스트

1. P0 — 실제 RigidBody3D 차량, 4륜 독립 지면 감지, 안정적인 접촉과 복구.
2. P0 — 휠 회전·기어비·RPM을 연결하고 P/R/N/D 및 자동·수동 변속을 테스트.
3. P0 — 보간 입력, 가독성 있는 실시간 HUD, 충돌 회피 카메라.
4. P1 — 조절 가능한 차량 리소스, 주행 보조, 저장/범위 제한.
5. P1 — 차체·독립 바퀴·실내·PBR 재질. 접지 상태와 휠 비율 확인.
6. P1 — 연결 도로망, 날씨·시간·교통·오디오, 실제 목표가 있는 모드.
7. P1 — 그래픽 부하 조절 및 GPU 측정.
8. P2 — LOD·청크 로딩 개선, 상세 UI 검증, 독립 실행 패키징.

프레임 저하의 원인을 영상에서 측정할 수는 없다. 높은 식생 밀도, 긴 그림자 거리, 반사, 과도한 개별 draw call은 일반적인 위험 요인으로만 분류했고, 새 프로젝트의 실제 렌더링 수치는 별도 테스트 결과로 기록한다.
